# Retrospective 1

## 1. Objetivo

Analizar qué funcionó bien, qué fue difícil y qué se debe mejorar para futuros sprints del proyecto Dream House S.A., tomando como referencia la realidad del Sprint 1 realizado en 2 horas.

---

## 2. Qué salió bien

- La estructura del proyecto ya estaba definida.
- El proyecto tenía una base clara de Java/JSP y conexión JDBC.
- La base de datos del dominio ya estaba diseñada y documentada.
- El alcance del sprint quedó bien delimitado para un tiempo limitado.
- La documentación del sprint fue clara y permitió mantener la visión del proyecto.

---

## 3. Qué fue difícil

- El tiempo disponible fue muy corto para cubrir todo el alcance funcional del parcial.
- La autenticación real completa requiere más validaciones y seguridad que la base actual.
- La diferencia entre “simulacro” y “parcial” exige disciplina para no sobreestimar el alcance entregado.
- La integración real de roles, sesiones y redirección debe validarse con mayor profundidad en pruebas.

---

## 4. Qué aprendimos

- No debemos mezclar “proyecto base” con “proyecto terminado”.
- Un MVP de acceso es una entrega válida si se documenta claramente.
- La guía del parcial exige más que páginas JSP básicas: requiere dominio, seguridad y documentación.
- El sprint debe priorizar funcionalidad real y evitar scope innecesario para no perder tiempo.

---

## 5. Mejores prácticas para el próximo sprint

- Mantener un alcance realista según el tiempo disponible.
- Documentar claramente qué corresponde a la base del sistema y qué aún no está implementado.
- Priorizar autenticación, roles y sesiones antes de complejizar otros módulos.
- Segmentar mejor el trabajo para seguir el flujo: autenticación, negocio, pruebas y documentación.
- Separar la entrega funcional mínima de la visión completa del parcial.

---

## 6. Conclusión

El Sprint 1 fue valioso porque dejó la base del proceso de autenticación y definió la ruta de trabajo del proyecto. La principal lección es que el equipo debe mantener un enfoque disciplinado: entregar un MVP bien documentado, sin pretender que el alcance completo del parcial se resuelve en un sprint de dos horas.

La correcta interpretación del proyecto es clave para avanzar sin frustración ni sobreestimación del progreso.
